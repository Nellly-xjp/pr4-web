##  Опис предметної області (Варіант: Одяг та взуття)

В рамках практичної роботи було реалізовано вебсервіс для управління каталогом одягу та взуття. 

### Структура сутності `Clothes`:
- `id` (string) — унікальний ідентифікатор (UUID / String);
- `title` (string) — назва товару (наприклад, *"Джинси Slim Fit"*);
- `price` (number) — вартість у гривнях;
- `size` (string) — розмір (*"S"*, *"M"*, *"L"*, *"42"* тощо);
- `material` (string) — матеріал (*"Бавовна"*, *"Шкіра"*, *"Сітка/Текстиль"*);
- `color` (string) — колір товару.

---

##  Огляд виконаних рівнів

### **Рівень 1. Базовий: Ініціалізація та маршрутизація**
1. **Створення проєкту:** Створено новий проєкт NestJS за допомогою CLI у директорії `online-store`.
2. **Оголошення DTO:**
   - `CreateClothesDto` — містить поля `title`, `price`, `size`, `material`, `color`.
   - `UpdateClothesDto` — часткова версія `CreateClothesDto` (використовує `PartialType` з `@nestjs/mapped-types`).
3. **Маршрутизація контролера (`ClothesController`):**
   - Налаштовано базовий шлях `@Controller('clothes')`.
   - Додано обробники REST-методів: `GET`, `POST`, `PATCH`, `DELETE`.

---

### **Рівень 2. Повний REST CRUD, HTTP-статуси та In-Memory Service**
1. **Створення сервісу (`ClothesService`):**
   - Згенеровано провайдер сервісу через CLI (`nest g s clothes --no-spec`).
   - Створено приватне in-memory сховище `private items: ClothesItem[]` із початковими тестовими даними.
2. **Реалізація бізнес-логіки та обробки помилок:**
   - `findAll()` — повертає весь список товарів.
   - `findOne(id)` — знаходить товар за ID. У разі відсутності генерація `NotFoundException` (HTTP 404).
   - `create(dto)` — генерує унікальний ID за допомогою `randomUUID()` та додає новий товар.
   - `update(id, dto)` — знаходить та оновлює лише передані поля товару (або 404).
   - `remove(id)` — видаляє товар за ID із масиву (або 404).
3. **Впровадження залежностей (Dependency Injection) та HTTP-статуси:**
   - Сервіс впроваджено в `ClothesController` через конструктор.
   - Метод `POST` повертає статус **`201 Created`** (`@HttpCode(HttpStatus.CREATED)`).
   - Метод `DELETE` повертає статус **`204 No Content`** (`@HttpCode(HttpStatus.NO_CONTENT)`).

---

### **Рівень 3. Просунутий: Query-фільтрація, кастомні Headers та тестування**
1. **Query-параметри (Пошук та Пагінація):**
   - `@Query('search')` — реалізовано фільтрацію за підрядком у назві товару (`title`) без урахування регістру (`toLowerCase()`).
   - `@Query('limit')` — реалізовано обмеження кількості результатів у видачі.
2. **Кастомні HTTP-заголовки (Response Headers):**
   - До методу `GET /clothes` додано системні заголовки за допомогою декораторів:
     - `@Header('X-API-Version', '1.0')`
     - `@Header('X-Service-Status', 'operational')`
3. **Файл для тестування API:**
   - У корені проєкту створено файл `requests.http` для комплексної перевірки всіх ендпоінтів.
